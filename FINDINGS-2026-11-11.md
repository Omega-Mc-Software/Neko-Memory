## The test, and what 2,377 cycles actually did

`memtest.py` does three things, then logs one JSON line:

1. `remember(probe_tag, "During the <stamp> memory test, the qwen2.5:7b model wrote a probe fact into Neko-Memory.", "now")`
2. `think()`
3. `answer_verified("What probe fact did the qwen2.5:7b model write during the memory test?")`

Log span: `2026-10-08T23:15:34Z` through `2026-11-11T20:07:01Z`. 2,377 JSON cycles, 4,754 log lines, no broken JSON lines.

| step | result |
| --- | --- |
| remember | 2,377 ok, 0 fails |
| think | 2,377 `nothing new to consolidate`, 0 other |
| answer_verified | 2,244 refused or marked unknown, 109 other, 24 failed (HTTP 500 or a FAIL string) |
| cycle time | min 1.3s, max 512.9s, average 31.9s |

The check mostly refuses. That is the verifier doing the job it was built for. It is not evidence that the probe was recalled.

## Why remember succeeds and recall still misses

`remember()` writes a row in `facts`. It does not call `store()`, so it never inserts a raw `memories` row.

`think()` only replays `memories` where `consolidated = 0`. The table has 6 rows. All 6 are already consolidated. With an empty replay batch, think returns immediately and writes nothing. That is why every cycle says nothing new. The probe never enters the consolidation path.

`facts` has 2,949 rows. 2,941 of them are these probes. Each cycle uses a new entity id (`memtest-qwen25-<timestamp>`), attribute blank, story time the literal string `now`. `now` has no chapter or day number, so `story_seq` falls back to the unix clock. The facts exist. They are not a timeline of one thing.

`answer()` asks the chat model to pick exactly one entity from `SELECT DISTINCT entity`. That list is thousands of one-off probe tags plus a handful of real names. The question does not contain the tag just written, so the model cannot pick it. It usually returns none, or an old name. Recall then pads with cosine hits over the 6 raw memories, which are:

- Neko Omega built LedgerCat v1.2 for Jason Omega, her father.
- Test trace v3: the cabbit basemesh was verified real on Oct 1, 2026.
- what chapter does Neko break her leg in? (stored twice)
- Smoke test Oct 2: Neko shipped persona and reflection passes to memory_store v3.1
- one reflection about the store becoming an active entity

Those six, plus two links and three summaries from the early October smoke tests, are the entire non-probe store. `persona` is empty, so answers use the default "you are Neko" block. The raw answer then role-plays and invents (chapters, a broken leg, a ball of yarn). `answer_verified` extracts claims, checks them against only the retrieved text, and usually rewrites the answer into a refusal. One leak on 11 Nov at 14:57Z returned the Oct 2 smoke-test sentence as if it were the probe. The verifier is not perfect. It is the only part that usually says no.

So the standing result is: write works, consolidation never sees the write, retrieval cannot name the entity it just created, the generator invents, the checker mostly deletes the invention.

## What else shares the machine

Stopping the memory loop does not free the GPU box. This is omegaserver. Legion's code bench and Legion's Ollama were already stopped on 15 Oct and were not touched.

On this box, Ollama stays up because the uploader is using it. A memory probe and a video script evict each other's model. That showed up as a slow cycle or a 500 when qwen was not loaded, not as a second writer in `memory.db`. One HTTP 500 on the check was already noted at 04:14Z on 11 Nov. The tally above is 24 fails across the whole log, not 24 today.

`memwatch` will keep rendering the frozen log. The page is a picture of a stopped test, not a live one.

## Ideas, in the order I would actually try them

1. Do not restart the 20-minute loop. Another night of it only adds more one-off entities. The service is enabled, not masked. Starting it is one command when a new test exists.

2. The next test should be ten facts, then stop. One entity (or `store()` into raw memories, which is the path `think()` actually reads). Ask the exact sentence back. Pass only if the revised answer contains that sentence. Log the entity `answer()` picked and the evidence list, not just the final paragraph.

3. `resolve_entity` cannot be handed thousands of names. Either stop creating an entity per probe, or resolve by recent facts and a small alias list. Until that changes, a question about "the probe" will keep landing on the six old memories.

4. Set a persona that is a clerk, not a character, for the verify path. The empty persona table plus the default "you are Neko" prompt is why the raw answer writes fiction before the checker strips it.

5. Keep the verifier. Do not "fix" refusals by loosening it. The bug is upstream of the refusal.

6. Split models if both jobs stay. The uploader's ministral and the memory probe's qwen should not take turns on one Ollama if either job cares about latency. Separate port, or run memory only when the uploader is idle.

7. The 2,941 probe facts are debris. Keep the 6 memories and 3 summaries. A later cleanup can delete entities matching `memtest-%` once we have copied the log off. Not done in this stop. `memory.db` was about 865 KB at stop. The log is about 1.8 MB.

8. This git repo's last commit before this note is 3 Oct (`f6a169e`). The running copy is `/home/neko/memory` on omegaserver, files dated 8 Oct for the scripts and 9 Oct for `render_memwatch.py`. This document describes the running copy. It does not claim the repo snapshot and the box are the same file.
